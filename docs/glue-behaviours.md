# Glue behaviours the integration suites assert

These behaviours of Glue, Athena and Spark are not documented as
contracts, and the construct relies on some of them; each row holds as
of the last green run of the Integration test workflow
(`.github/workflows/integ-test.yml`) and is asserted by the script and
assertion named, which `grep` finds. Read this before changing how the
construct numbers fields or builds an update.

| Observed | Script and assertion |
| --- | --- |
| CREATE renumbers fields in creation order ([rule](https://github.com/ksco92/arceus/blob/main/README.md#creation-order)). | `scripts/integration-test-surface.sh`: `assert_stored_ids creation_order_test` under `VERIFY 2b`; `VERIFY 2a` for tables declared in creation order. |
| A table declared out of creation order (`a` 2, `b` 1) takes the declared ids on its first update, a table property change alone; Athena then reads `a` of the row written before it with `b`'s value and `b` with `a`'s ([rule](https://github.com/ksco92/arceus/blob/main/README.md#the-field-id-rules)). | `scripts/integration-test-evolution.sh`: `assert_meta columns "2:a,1:b" "$RENUMBER_TABLE"` under `VERIFY step 2 (renumber_test, format_version_test, decimal_test)`, `athena_expect "a and b of the row written before the first update read each other's values"` under `ATHENA step 2`. |
| UpdateTable stores declared column and nested ids as given, including an id out of creation order and the gap a dropped column leaves. | `scripts/integration-test-evolution.sh`: `assert_nested_ids` under `VERIFY step 8`, `assert_columns` under `VERIFY step 12`, `last-column-id stays at 4 — id reuse protection` under `VERIFY step 4`. |
| On a v3 table the partition field ids and `last-partition-id` after a partition evolution are `1002:month,1001:hour` and 1002; in both evolution scripts `last-partition-id` is at least the highest declared id. | `scripts/integration-test-v3-evolution.sh`: `verify_step` and `assert_equals "last-partition-id" "1002"` at step 4. `assert_partition_history`, called from both evolution scripts, fails on `STALE COUNTER` and on `CONFLICT`. |
| An update that gives a dropped column's id to a new column of another name and the same type is accepted, the current schema holds the id under the new name, `last-column-id` does not move, and Spark and Athena read the dropped column's value, in the row written before the drop, as the new column's value. | `scripts/integration-test-evolution.sh`: `deploy_step 3` under `set -euo pipefail`, `assert_meta columns "1:a,2:d" "$REUSED_TABLE"` and `assert_meta last-column-id 2 "$REUSED_TABLE"` under `VERIFY step 3 (reused_id_test, partition_id_test)`, `athena_expect "d of the row written before the drop reads c's value"` under `ATHENA step 3`; `scripts/spark/verify_evolution.py`: `row written before c was dropped` in `phase_3`. |
| A partition field added under a `fieldId` above the next free id is stored with that id and `last-partition-id` becomes it (1005 after 1000 and 1001); a field added later under an unused id below `last-partition-id` (1003) is stored with that id and `last-partition-id` stays 1005. | `scripts/integration-test-evolution.sh`: `assert_meta partition-ids` and `assert_meta last-partition-id 1005` under `VERIFY step 2 (reused_id_test, partition_id_test)` and `VERIFY step 3 (reused_id_test, partition_id_test)`. |
| CREATE numbers partition fields 1000, 1001 and up in spec order and ignores the declared `fieldId`s: a table declared 1005 on the first field and 1000 on the second is stored with 1000 and 1001, and `last-partition-id` is 1001 ([paragraph](https://github.com/ksco92/arceus/blob/main/README.md#partition-fields)). | `scripts/integration-test-evolution.sh`: `assert_meta partition-ids "1000:day,1001:bucket[4]"` and `assert_meta last-partition-id 1001` under `VERIFY step 1 (create_partition_id_test, declared 1005 then 1000)`. |
| An update whose only change to a table is its `Name` going from a literal to a `Ref` of a parameter whose default is the same string leaves the Glue table as it was: `VersionId` 1 and the `00001-` `metadata_location` its one write left, and that write's row reads back. | `scripts/integration-test-evolution.sh`: `assert_same "${NAME_TABLE} Glue version and metadata file" "1 00001"` under `VERIFY step 9 (parameter_name_test)`, `athena_expect "${NAME_TABLE} row written at step 1"` under `ATHENA step 9`. |
| An update whose fields match an earlier schema makes that schema current again and adds none, though the construct sends `schemaId: 0`. | `scripts/integration-test-evolution.sh`: `assert_meta schema-id "$ROLLED_BACK_SCHEMA_ID"` and `assert_meta schemas-count $((SCHEMAS_BEFORE + 1))` under `VERIFY step 12`. |
| An update whose partition spec matches one the table holds adds no spec: the current one, and an earlier one, which becomes the default again. | `scripts/integration-test-evolution.sh`: `assert_meta spec-count 1` under `VERIFY step 2 (ADD column)`; `assert_meta spec-count 2` and `assert_meta default-spec-id 0` under `VERIFY step 4 (DROP column + DROP partition)`. |
| A table property update of a table with a `decimal(10, 2)` column adds no schema. | `scripts/integration-test-evolution.sh`: `assert_meta commit-retries 5 "$DECIMAL_TABLE"` and `assert_meta schemas-count 1 "$DECIMAL_TABLE"` under `VERIFY step 2 (renumber_test, format_version_test, decimal_test)`. |
| Property-only update ([paragraph](https://github.com/ksco92/arceus/blob/main/README.md#identifiers-sort-order-and-table-properties)). | `scripts/integration-test-evolution.sh`: `assert_meta commit-retries 5`, `assert_same "rest of metadata.json unchanged"` under `VERIFY step 9`. |
| Changed sort order ([paragraph](https://github.com/ksco92/arceus/blob/main/README.md#identifiers-sort-order-and-table-properties)). | `scripts/integration-test-evolution.sh`: `assert_meta sort-orders "1:identity(1)/asc/nulls-last;2:`, `assert_meta default-sort-order-id 2` under `VERIFY step 10 (sort order change)`. |
| A changed `identifierFieldNames` on a `(PK) `-marked table changes `identifier-field-ids`. | `scripts/integration-test-evolution.sh`: `assert_identifiers "2" "contact_email"` under `VERIFY step 6`. |
| On a table created with identifier id 1 and no `(PK) ` marker, which a later update marks, an update that removes the identifier makes the unmarked schema 0 current again with `identifier-field-ids` 1 and adds no schema; the same removal together with a `doc` added to another column adds a schema with no identifier ids ([limitation](https://github.com/ksco92/arceus/blob/main/README.md#known-limitations)). | `scripts/integration-test-evolution.sh`: `assert_meta schema-id 0 "$UNMARKED_TABLE"`, `assert_meta schemas-count 2 "$UNMARKED_TABLE"`, `assert_meta identifier-field-ids 1 "$UNMARKED_TABLE"`, `assert_meta schema-id 2 "$UNMARKED_DOC_TABLE"` and `assert_meta identifier-field-ids "" "$UNMARKED_DOC_TABLE"` under `VERIFY step 3 (unmarked_identifier_test, unmarked_identifier_doc_test)`. |
| Rolled-back deploy ([limitation](https://github.com/ksco92/arceus/blob/main/README.md#changes-that-need-care)). | `scripts/integration-test-evolution.sh`: `stack status`, `current schema, columns and orders as before step 11`, `assert_meta last-column-id 5`, `assert_meta schemas-count` under `VERIFY step 11`. |
| An update that changes `formatVersion` from V2 to V3 keeps the table's `table-uuid` and its `format-version` 2, and `properties.format-version` reads `3` ([limitation](https://github.com/ksco92/arceus/blob/main/README.md#changes-that-need-care)). | `scripts/integration-test-evolution.sh`: `assert_meta format-version 2 "$FORMAT_TABLE"`, `assert_meta properties-format-version 3 "$FORMAT_TABLE"` and `assert_meta table-uuid "$FORMAT_UUID" "$FORMAT_TABLE"` under `VERIFY step 2 (renumber_test, format_version_test, decimal_test)`. |
| An update that drops a column together with the partition field it sources is accepted, and `SELECT *` and `SELECT count(*)` from the table, which holds a row written before the update, then fail in Athena with `GENERIC_INTERNAL_ERROR: Type cannot be null`. On a second table an update that removes the partition field and keeps the column leaves that row readable, and a later update that drops the column fails both queries the same way ([limitation](https://github.com/ksco92/arceus/blob/main/README.md#changes-that-need-care)). | `scripts/integration-test-evolution.sh`: `deploy_step 2` and `deploy_step 3` under `set -euo pipefail`; `athena_expect_failure "${DROP_SOURCE_TABLE} after cat and its partition field are dropped together"`, `athena_expect_failure "count(*) on ${DROP_SOURCE_TABLE} after cat and its partition field are dropped together"` and `athena_expect "${DROP_SOURCE_LATER_TABLE} after its partition field on cat is removed"` under `ATHENA step 2`; `athena_expect_failure "${DROP_SOURCE_LATER_TABLE} after cat is dropped"` and `athena_expect_failure "count(*) on ${DROP_SOURCE_LATER_TABLE} after cat is dropped"` under `ATHENA step 3`. |
| An update that gives partition field id 1000, held by `bucket[4]` of `id`, to `bucket[8]` of `id` is accepted; Athena reads the row written before it, and a Spark `SELECT *` from the table fails with `ValidationException: Conflicting partition fields` naming both fields ([rule](https://github.com/ksco92/arceus/blob/main/README.md#the-field-id-rules)). | `scripts/integration-test-evolution.sh`: `deploy_step 2` under `set -euo pipefail`; `athena_expect "${REUSED_PARTITION_TABLE} after bucket[8] takes field id 1000 from bucket[4]"` under `ATHENA step 2`; `scripts/spark/verify_evolution.py`: `CONFLICT` in `phase_2`. |

| A raw `AWS::Glue::Table` with `tableInput`, holding only a `name`, beside `openTableFormatInput.icebergInput.icebergTableInput` fails to create; with the request token removed, the CloudFormation event's reason is `Resource handler returned message: "Table metadata is expected only via TableInput or via IcebergTableInput inside OpenTableFormatInput" (HandlerErrorCode: InvalidRequest)`, and the deploy that adds it after an update of another table ends in `UPDATE_ROLLBACK_COMPLETE` ([section](https://github.com/ksco92/arceus/blob/main/README.md#tableinput-beside-icebergtableinput)). | `scripts/integration-test-evolution.sh`: `stack status` and `only TableInputTable failed` under `VERIFY step 11 (rolled back)`. |
